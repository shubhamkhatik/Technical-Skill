# AI System Design

## AI/LLM Discoverability (GEO/AEO)

| **Method / Domain**         | **Core Concepts**                                                                             | **Tools & Specifications**                       | **Key Techniques**                                                                                               | **Tradeoffs & Operational Limits**                                                                                             |
| --------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **The `llms.txt` Standard** | Machine-readable site mapping, curated knowledge indexing, feeding bots dense contextual data | Next.js API Routes, `llms.txt` spec              | Dynamic generation of Markdown summaries, advertising `llms-full.txt` payloads via response headers              | Hard LLM context limits (~100k chars) lead to silent truncation; requires strict cache invalidation to prevent hallucinations. |
| **Content Negotiation**     | Bypassing HTML token bloat, intercepting AI crawlers before they hit the frontend             | Next.js Edge Middleware, User-Agent parsing      | Detecting `GPTBot`, `ClaudeBot`, `Google-Extended`; transparently rewriting requests to a dedicated Markdown API | Bypasses standard web analytics; requires maintaining a separate rendering pipeline just for Markdown extraction.              |
| **Semantic Scaffolding**    | Pre-hydrated payloads, explicit entity definition, bypassing JS execution limits of bots      | React Server Components (RSC), Schema.org, HTML5 | Wrapping claims in `<article>`/`<blockquote>`, injecting structured `JSON-LD` directly into the DOM              | Highly effective for docs/blogs, but ineffective for authenticated dashboards or highly interactive UI states.                 |
| **GEO Observability**       | Monitoring ingestion rates, protecting origin databases from massive bot scraping             | Vercel Data Cache, Redis, Datadog, New Relic     | Correlating Edge/WAF logs for AI agents with Google Search Console Generative AI metrics                         | Standard client-side tracking (e.g., Google Analytics pixels) will not detect these headless bot hits.                         |

| **Method / Domain**                           | **Core Concepts**                                                                                                                                                                                                                                                       | **Tools & Specifications**                                                                                                                           | **Key Techniques**                                                                                                                                                                                                                                                              | **Tradeoffs & Operational Limits**                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Robots.txt / AI Crawler Directives**        | The blunt, standardized opt-out mechanism that comes *before* any custom middleware logic — a plain-text file at your root telling bots what they can and can't touch. Every major AI crawler now respects its own named directive, separately from regular search bots | `robots.txt` at site root, per-bot `User-agent` blocks (`GPTBot`, `ClaudeBot`, `Google-Extended`, `PerplexityBot`, `CCBot`)                          | Explicit allow/disallow rules per bot — e.g. block `GPTBot` from training-data scraping while still allowing `ChatGPT-User` (the one that fetches pages live when a user asks ChatGPT to browse). These are different UAs with different intents, easy to conflate              | ✅ Zero infra cost, works before a request even reaches your server ❌ It's an honor system — nothing stops a bot from ignoring it entirely. Also: blocking `GPTBot` doesn't stop your content from being cited if it was scraped before you added the rule, or if a *different* pipeline (like a search-grounded answer) pulls from a search index that already has you indexed |
| **Citation & Attribution Tracking**           | The actual end goal of GEO isn't "let bots crawl me cleanly" — it's "get mentioned/cited when someone asks an AI a relevant question." This is the metric almost nobody in the infra-focused half of GEO is measuring                                                   | Tools like Profound, Otterly, Peec AI — built specifically to monitor brand mentions inside ChatGPT/Perplexity/Gemini responses, not just crawl logs | Run sample prompts regularly against target queries, track whether/how your brand or content gets referenced, monitor share-of-voice against competitors in AI answers the same way you'd track SEO rank                                                                        | ✅ This is the only way to know if any of your GEO work is actually working, not just theoretically sound ❌ Immature tooling category — these products are new, sampling-based (you can't query "every possible prompt"), and results can shift run-to-run since LLM outputs aren't deterministic. Treat numbers as directional, not precise                                    |
| **Answer-Format Optimization (the AEO half)** | Everything upstream in this table is about how bots *fetch* you. This is about how your content should be *structured* so it's easy to lift out as a direct answer — the actual "Answer Engine Optimization" half that's been mostly missing                            | FAQ schema (`FAQPage` JSON-LD), question-shaped H2/H3 headers, "answer-first" paragraph structure                                                    | Lead with a direct, complete answer in the first 1-2 sentences before elaborating — mirrors how featured snippets worked in classic SEO, but now it's what gets lifted into an LLM's synthesized answer. Structure content as explicit Q&A where it makes sense, not just prose | ✅ Doubles as classic SEO snippet optimization, so it's not wasted effort even if GEO fizzles ❌ Over-optimizing for "extractability" can make content read as robotic or overly formulaic — there's a real tension between "written for bots to lift" and "written for humans to actually enjoy reading"                                                                        |
| **Staleness & No-Recrawl Problem**            | Unlike search engines, most LLM providers have no equivalent of "request re-indexing." If an AI cites your old or wrong content, you often have no direct lever to force a fresh crawl — you just wait and hope                                                         | No standardized tool yet — this is closer to an open operational risk than a solved technique                                                        | Best current mitigation is aggressive `llms.txt` cache invalidation on your own end (so *if* a bot does re-fetch, it gets current data) plus monitoring (via citation tracking above) to catch when stale info is being served, so you at least know it's happening             | ❌ This is the least solved problem in the whole table. There's no reliable push mechanism to any major LLM provider's knowledge — you're dependent on their own re-crawl schedules, which are opaque and provider-specific. Worth treating as a known limitation, not something you can engineer around yet                                                                    |

## Enterprise RAG Architecture (10M Docs, Zero Hallucinations)

| **System Component**                | **Core Concepts & Architecture**                                                                                               | **Tools & Infrastructure**                          | **Key Techniques**                                                                                                                                       | **Tradeoffs & Operational Limits**                                                                                                                                      |
| :---------------------------------- | :----------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Production Scale RAG (10M Docs)** | Multi-tier architecture decoupling raw document blobs, relational metadata, and vector index for 200+ QPS read-heavy workloads | S3, PostgreSQL, Qdrant (HNSW), Elasticsearch, Redis | Dual-path: Ingestion via S3 + sentence-chunking (32-token overlap); Query via Redis semantic cache -> parallel Qdrant/ES scatter -> RRF -> Cross-encoder | ✅ P50 < 1.5s, P99 < 5s at 10M doc scale; ACID metadata consistency in Postgres ❌ High RAM footprint for HNSW graph (~1.5x vector size; requires Product Quantization)   |
| **Zero-Hallucination Guardrails**   | Multi-gate defense ensuring system never asserts claims unsupported by retrieved context                                       | NLI Cross-Encoder, `temperature=0`, Refusal tokens  | Gate 1: Retrieval confidence score check (>0.4); Gate 2: Prompt refusal prompt; Gate 3: Extract atomic claims and verify NLI entailment against passages | ✅ Guaranteed factual grounding; eliminates hallucinated claims in enterprise apps ❌ Increases P99 latency via post-generation NLI verification; false-positive refusals |
