# LLM Serving & Gateways

> **Mental Model:** Production AI backends require an abstraction layer between application code and raw LLM providers. This layer handles: (1) **Model Serving** (high-throughput GPU inference engines), (2) **Unified Gateway Routing** (standardizing 100+ provider APIs into one format), (3) **Semantic Caching** (eliminating redundant inference costs), and (4) **Resilience & Governance** (fallbacks, rate limiting, and cost controls).

## Unified LLM Gateways & Routing

| Topic / Skill                            | Core Concepts & Mental Model                                                                                                                                                                      | Tools & Libraries                                   | Key Techniques                                                                                                                               | Tradeoffs & Failure Modes                                                                                                                                                                                           | Resources                                                                                                             |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Unified API Gateway (LiteLLM)**        | Proxy layer standardizing 100+ LLM provider APIs (OpenAI, Anthropic, Bedrock, Vertex AI, Ollama) into a single unified OpenAI-compatible format                                                   | `LiteLLM Proxy`, `Portkey`, `Cloudflare AI Gateway` | Standardized request/response normalization, centralized virtual API key management, unified spend tracking per team/user                    | ✅ Write application code once against a single interface; switch providers without changing frontend/backend code ❌ Single point of failure if self-hosted without high availability; proxy hop adds 5–15ms latency | [LiteLLM Docs](https://docs.litellm.ai/), [Portkey Docs](https://docs.portkey.ai/)                                    |
| **Model Routing & Cascading**            | Dynamically routing incoming prompts to the optimal model based on task complexity, cost, or intent (e.g. simple queries $\rightarrow$ GPT-4o-mini; complex code $\rightarrow$ Claude 3.5 Sonnet) | `LiteLLM Router`, `Martian Router`, `RouteLLM`      | Prompt classifier / embedding router, tiered latency/cost rules, semantic intent detection                                                   | ✅ Reduces API costs by 50–80% without sacrificing quality on hard tasks ❌ Routing classifier error can send hard tasks to weak models, degrading response quality                                                   | [RouteLLM GitHub](https://github.com/lm-sys/RouteLLM), [LiteLLM Load Balancing](https://docs.litellm.ai/docs/routing) |
| **Fallback Cascades & Circuit Breakers** | Automatic failover when the primary LLM provider suffers outages, rate limits (HTTP 429), or server errors (HTTP 5xx)                                                                             | `LiteLLM`, `tenacity`, `resilience4j`               | Fallback list (`openai/gpt-4o` $\rightarrow$ `anthropic/claude-3-5-sonnet` $\rightarrow$ `bedrock/llama-3`), exponential backoff with jitter | ✅ High availability (99.99%); seamless survival through major cloud provider outages ❌ Different models have slight differences in prompt adherence, system instructions, and tool calling schemas                  | [LiteLLM Fallbacks](https://docs.litellm.ai/docs/proxy/reliability)                                                   |

## Semantic Caching & Rate Limiting

| Topic / Skill               | Core Concepts & Mental Model                                                                                                                | Tools & Libraries                             | Key Techniques                                                                                                                          | Tradeoffs & Failure Modes                                                                                                                                    | Resources                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| **Semantic Prompt Caching** | Caching LLM responses based on semantic similarity of input prompts rather than exact string matches, intercepting queries before the model | `GPTCache`, `Redis` (`RediSearch`), `Upstash` | Cosine similarity calibration (starting sweet spot $\approx 0.85$), evaluation against paraphrased vs near-miss query traps, TTL expiry | ✅ Sub-50ms latency, zero token cost on static FAQ queries ❌ Threshold too low causes false-positive near-misses; threshold too high causes hit-rate collapse | [GPTCache Docs](https://gptcache.readthedocs.io/), [Redis Semantic Cache](https://redis.io/solutions/semantic-caching/) |

| **Provider Prompt Caching**             | Reusing key-value attention states for static, long prompt prefixes (e.g. large system prompts, codebases, or reference docs) directly on provider GPUs                       | Anthropic Prompt Caching, OpenAI Prompt Caching                 | Structure prompts with static prefixes first (`cache_control: {"type": "ephemeral"}`), minimum token threshold (1024 tokens) | ✅ Up to 90% cheaper input tokens and 80% faster Time to First Token (TTFT) on long prompts ❌ Cached prefix is invalidated on any upstream character change; ephemeral cache expires after 5 minutes of inactivity | [Anthropic Prompt Caching](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching), [OpenAI Prompt Caching](https://platform.openai.com/docs/guides/prompt-caching) |
| **Token-Bucket Rate Limiting & Quotas** | Controlling request velocity and token consumption per user, team, or API key to prevent provider quota exhaustion and runaway costs                                          | `LiteLLM Proxy`, `Redis` (`token-bucket`), `@upstash/ratelimit` | TPM (Tokens Per Minute) and RPM (Requests Per Minute) tracking, HTTP 429 backoff headers, user-tier quotas                   | ✅ Protects infrastructure from noisy neighbors; prevents sudden budget spikes ❌ Users get blocked during legitimate traffic bursts unless burst allowances are tuned                                              | [LiteLLM Rate Limiting](https://docs.litellm.ai/docs/proxy/users)                                                                                                                |
