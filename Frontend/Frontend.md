## Bundler

| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Entry Points               | Dependency graph starts from entry; multiple entries enable per-route code splitting                                                             | Webpack `entry`, Vite `build.rollupOptions.input`                                             | Multi-entry setup, dynamic `import()` for lazy-loaded routes                                                               | [Webpack Entry](https://webpack.js.org/concepts/entry-points), [Vite build options](https://vitejs.dev/config/build-options) |
| Loaders vs Plugins         | *Loaders* transform individual file types (TS→JS, SCSS→CSS); *Plugins* operate on the full build pipeline — these are different responsibilities | `babel-loader`, `ts-loader`, `sass-loader`, `HtmlWebpackPlugin`, `DefinePlugin`, Vite plugins | File transformation pipeline, env variable injection (`DefinePlugin`), HTML templating, compression                        | [Webpack Loaders](https://webpack.js.org/loaders), [Webpack Plugins](https://webpack.js.org/plugins)                         |
| Output & Cache Busting     | Content hashing ties filename to file content; browsers cache aggressively — changing content = new filename = fresh fetch                       | Webpack `output`, Vite `build.outDir`                                                         | `[contenthash]` in filenames, vendor chunk naming, `publicPath` config                                                     | [Webpack Output](https://webpack.js.org/concepts/output)                                                                     |
| Code Splitting             | Reduce initial bundle size; load code only when needed                                                                                           | Webpack `splitChunks`, Vite dynamic imports, `React.lazy`                                     | Route-based splitting, dynamic `import()`, `SplitChunksPlugin` config, async chunks                                        | [web.dev – Code Splitting](https://web.dev/articles/code-splitting-with-dynamic-imports-in-nextjs)                           |
| Tree Shaking               | Dead code elimination via static analysis — only works with ES module syntax (`import`/`export`)                                                 | Rollup (built-in), Webpack 5                                                                  | Mark packages as side-effect-free (`"sideEffects": false` in `package.json`), avoid CommonJS, avoid barrel file re-exports | [Webpack Tree Shaking](https://webpack.js.org/guides/tree-shaking)                                                           |
| Minification & Compression | Reduce file size for transfer and parse time; separate concerns (JS vs CSS vs assets)                                                            | TerserPlugin, esbuild, cssnano, gzip / Brotli (server/CDN)                                    | JS minification via Terser/esbuild, CSS via cssnano, gzip/Brotli at CDN level, disable source maps in production           | [Terser docs](https://terser.org/)                                                                                           |
| Developer Experience       | Fast feedback loop without full rebuild; debuggable minified code in dev                                                                         | Vite HMR, Webpack Dev Server, `source-map`, `eval-source-map`                                 | HMR setup, source map strategy (`cheap-module-source-map` for dev, `hidden-source-map` for prod), incremental builds       | [Vite guide](https://vitejs.dev/guide), [Webpack DevServer](https://webpack.js.org/configuration/dev-server)                 |
