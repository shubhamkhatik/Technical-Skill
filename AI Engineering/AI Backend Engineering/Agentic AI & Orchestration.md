# Agentic AI & Orchestration

> **Mental Model:** AI Agents shift LLMs from static text generators into autonomous decision-making systems. An agent loop operates on: (1) **Perception** (user goal + environment state), (2) **Reasoning** (ReAct / planning steps), (3) **Action** (Tool/API calling via structured contracts like MCP), and (4) **Observation & Reflection** (handling feedback and iterating until completion).

| **Function Calling & Tool Execution** | Model outputs a structured JSON call matching a registered schema rather than plain text. The runtime executes the local/remote code and returns results to the LLM | OpenAI Function Calling, Anthropic Tools, `Pydantic`, `Zod` | JSON Schema generation from type definitions, parameter coercion, injecting execution output back into message history as `tool` role | ✅ Connects LLMs to live databases, internal APIs, and code execution ❌ Model can hallucinate parameters or invalid types; executing destructive actions without safeguards causes irreversible side-effects | [OpenAI Function Calling Guide](https://platform.openai.com/docs/guides/function-calling), [Anthropic Tool Use](https://docs.anthropic.com/en/docs/build-with-claude/tool-use) |
| **Parallel Tool Calling** | Model predicts and invokes multiple independent tool calls in a single turn (e.g. fetching weather for 3 cities simultaneously) | OpenAI / Claude native API, `asyncio`, `Promise.all` | Parallel asynchronous execution, error handling per call (partial success), aggregating responses into a single follow-up prompt | ✅ Drastically reduces multi-turn latency when retrieving independent data sources ❌ Increased rate-limit risks on downstream APIs; if one tool fails, the model must know how to handle partial failure gracefully | [OpenAI Parallel Function Calling](https://platform.openai.com/docs/guides/function-calling#parallel-tool-calling) |
| **Tool Error Recovery & Self-Correction** | Passing runtime error messages, validation failures, or stack traces back to the LLM so it can analyze the error and retry with corrected parameters | Custom loop handler, `tenacity` (Python), `p-retry` (JS) | Capture exception string, append as tool response, prompt LLM: *"Function failed with Error X. Adjust arguments and retry."* | ✅ Autonomous self-healing for bad SQL, wrong parameters, or missing fields ❌ Infinite retry loops if the error is unrecoverable (e.g. auth failure); wastes tokens without strict retry caps (max 2–3 retries) | — |

## Model Context Protocol (MCP)

| Topic / Skill | Core Concepts & Mental Model | Tools & Libraries | Key Techniques | Tradeoffs & Failure Modes | Resources |
| --- | --- | --- | --- | --- | --- |
| **Model Context Protocol (MCP)** | Open standard created by Anthropic that standardizes how LLM applications (hosts/clients) connect to external tools, databases, and context servers via a unified protocol | `@modelcontextprotocol/sdk`, Python `mcp` library | Client-Host-Server architecture: Client connects to MCP servers, discovers capabilities dynamically, and executes tools | ✅ Solves the $N \times M$ integration problem (one MCP server works with Claude, Antigravity, Cursor, etc.) ❌ Added protocol abstraction overhead; immature ecosystem with evolving specs | [Model Context Protocol Docs](https://modelcontextprotocol.io/) |
| **MCP Primitives (Tools, Resources, Prompts)** | Core building blocks exposed by an MCP Server: Tools (callable functions), Resources (readable data/files), and Prompts (reusable workflow templates) | Python `FastMCP`, TypeScript MCP SDK | Expose tools via decorators (`@mcp.tool()`), define URI schemes for resources (`file://`, `db://`), parameterized prompt templates | ✅ Unified interface for data access, dynamic tooling, and user interactions ❌ Resources must handle large payload streaming; tools need strict permission scoping | [MCP Primitives Guide](https://modelcontextprotocol.io/docs/concepts/tools) |
| **MCP Transports (stdio vs SSE)** | Communication channels between MCP clients and servers. `stdio` runs local child processes; `SSE` (Server-Sent Events) connects to remote network services | `stdio`, HTTP + SSE, WebSockets | `stdio` for local CLI tools, scripts, and local DBs; `SSE` for centralized remote microservices with authentication headers | ✅ `stdio` requires zero port/networking setup; `SSE` enables shared enterprise MCP servers ❌ `stdio` processes cannot be easily shared across machines; `SSE` requires robust auth, CORS, and proxy management | [MCP Architecture](https://modelcontextprotocol.io/docs/concepts/architecture) |

## Agent State Machines & Loops (LangGraph, ReAct)

| Topic / Skill | Core Concepts & Mental Model | Tools & Libraries | Key Techniques | Tradeoffs & Failure Modes | Resources |
| --- | --- | --- | --- | --- | --- |
| **ReAct Loop (Reason + Act)** | Foundational agent loop alternating between **Thought** (reasoning what to do), **Action** (calling a tool), and **Observation** (reading tool output) until final answer | `LangGraph`, `LlamaIndex Workflows` | Interleave thought and action tokens, stop sequences on tool calls, observation injection | ✅ Explainable reasoning step-by-step; recovers from partial tool errors ❌ Linear execution prone to looping; token-heavy as conversation history accumulates | [ReAct Paper (Yao et al.)](https://arxiv.org/abs/2210.03629) |
| **State Machine Graphs (LangGraph)** | Models complex agent workflows as state graphs with nodes (actions/LLM calls), edges (conditional transitions), and persistent shared state | `LangGraph`, `LangGraph Studio` | Define `TypedDict` / Pydantic state, conditional routing (`add_conditional_edges`), cyclical loops, sub-graphs | ✅ Full control over cyclical logic (unlike linear DAGs), deterministic branch routing, easy to test individual nodes ❌ Steeper learning curve than simple chains; state schema design requires upfront rigor | [LangGraph Docs](https://langchain-ai.github.io/langgraph/) |
| **State Checkpointing & Time Travel** | Persisting graph state to a storage backend at every superstep, enabling pause/resume, rollback, and replaying from previous execution points | `SqliteSaver`, `PostgresSaver` (LangGraph) | Snapshot state after each node execution, restore graph execution from thread ID, modify state at step $T$ and branch | ✅ Essential for production resilience, debugging non-deterministic agent runs, and human-in-the-loop approvals ❌ Storage overhead grows with long threads; complex schema migrations on active threads | [LangGraph Persistence](https://langchain-ai.github.io/langgraph/how-tos/persistence/) |

## Multi-Agent Systems & Human-in-the-Loop

| Topic / Skill | Core Concepts & Mental Model | Tools & Libraries | Key Techniques | Tradeoffs & Failure Modes | Resources |
| --- | --- | --- | --- | --- | --- |
| **Supervisor / Hierarchical Pattern** | A central supervisor LLM breaks down high-level user tasks and orchestrates specialized worker agents (e.g. Researcher, Coder, Reviewer) | `LangGraph`, `CrewAI`, `AutoGen` | Task delegation via tool calls, worker output aggregation, dynamic worker routing based on intermediate results | ✅ Clear separation of concerns, specialized system prompts per agent reduce context bloat ❌ Supervisor becomes a single point of failure; token costs scale linearly with the number of worker agents | [LangGraph Multi-Agent Workflows](https://langchain-ai.github.io/langgraph/tutorials/multi_agent/agent_supervisor/) |
| **Human-in-the-Loop (HITL)** | Pausing agent execution before high-stakes, irreversible, or costly actions (e.g. database updates, payments, sending emails) to require explicit human approval | LangGraph `interrupt()`, Webhooks, Slack bot | Interrupt execution at sensitive node, notify human with action payload, resume with `approve` or modified parameters | ✅ Prevents autonomous disasters; meets enterprise compliance and safety requirements ❌ Pauses asynchronous pipelines; requires stateful persistence to wait hours/days for human review | [LangGraph Human-in-the-Loop](https://langchain-ai.github.io/langgraph/how-tos/human-in-the-loop/) |
| **Execution Budgets & Loop Guardrails** | Enforcing strict limits on recursion depth, step counts, wall-clock time, and total token expenditure to prevent runaway autonomous loops | `max_iterations`, token budget counters, timeout signals | Hard cap on loop steps (`max_iterations = 10`), circuit breaker pattern when budget is exceeded, fallback to safe error state | ✅ Protects against infinite loops and multi-hundred-dollar API bills from hallucinating agents ❌ Premature termination of complex multi-step reasoning tasks if budget is set too tight | [LangChain Loop Limits](https://python.langchain.com/docs/how_to/) |
